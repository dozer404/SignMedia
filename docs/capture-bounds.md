# Dual-Token Capture Time Bounds Specification

This specification defines the authenticated dual-token protocol for proving physical capture interval bounds using cryptographic timestamps and hardware/pipeline attestation.

## 1. Threat Model & Assumptions
Timestamps over arbitrary media files prove only that data existed prior to the timestamp. They do **not** establish when physical photons hit a sensor unless the capture pipeline cryptographically links an unpredictable challenge, sensor attestation, content commitment, and time-stamps.

### Assumptions
- **Unpredictable Pre-Capture Challenge ($C_1$)**: Generated by a trusted server or beacon, preventing pre-computation.
- **Hardware/Pipeline Attestation**: The capture device's isolated hardware (TPM / Secure Enclave) or attested capture software binds the challenge $C_1$ and sensor output before application software can modify frames.
- **Trusted Time Stamp Authorities ($TSA_1, TSA_2$)**: Independent, accredited RFC 3161 Time Stamp Authorities.

## 2. Protocol Mechanics

### Step 1: Pre-Capture Challenge ($T_1$)
Prior to recording, the capture device fetches an unpredictable server nonce $C_1$ (e.g. recent block hash or TSA challenge).
The device requests pre-capture token $T_1 = \text{TSA}_1.\text{stamp}(C_1)$.

### Step 2: Authenticated Capture Commitment
During media capture ($M$), the isolated sensor/pipeline constructs the capture commitment:
$$\text{Commitment} = H(C_1 \parallel \text{SensorID} \parallel \text{AttestationStatement} \parallel H(M))$$
The hardware attests this commitment using its device key.

### Step 3: Post-Capture Token ($T_2$)
Immediately upon capture completion, the device requests post-capture token:
$$T_2 = \text{TSA}_2.\text{stamp}(H(\text{Commitment} \parallel H(T_1)))$$

## 3. Replay Defenses & Verification Rules

A validator evaluates the capture time interval $(T_1.\text{time}, T_2.\text{time})$ as valid **only if**:
1. Both $T_1$ and $T_2$ contain valid CMS signatures and imprints matching the registered TSA trust anchors.
2. $T_1.\text{imprint} == H(C_1)$ and $T_2.\text{imprint} == H(\text{Commitment} \parallel H(T_1))$.
3. $T_1.\text{time} < T_2.\text{time}$ and $T_2.\text{time} - T_1.\text{time} \le \text{MaxAllowedCaptureDuration}$.
4. The hardware/pipeline attestation statement for $\text{Commitment}$ is verified against a trusted device credential chain.

Without valid attestation, the interval represents only data-existence bounds rather than physical sensor capture bounds.
